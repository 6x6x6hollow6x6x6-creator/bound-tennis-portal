## この案件の経緯

協会から「全国各地のローカル大会情報のまとめサイトがほしい」「いろんな大会を含めた日本ランキングを作りたい
（硬式テニスのJOPみたいな感じ）」という相談があり、たたき台を作っている段階。

デザインの方向性は何度か往復した結果、**日本バウンドテニス協会サイト（boundtennis.or.jp）の配色・レイアウト準拠**で確定。
実際にブラウザで開いて色を拾った：ネイビー `#001F33`、レッド `#B50000`、背景 `#F1F1F1`、罫線 `#E2E2E2`、本文 `#222`。
書体も協会サイトと同じ `Helvetica Neue → Hiragino Kaku Gothic ProN` の指定にしてある。

アーキテクチャは、依頼者が以前 Claude Code で作った**石川県バウンドテニス協会サイト（ibta.info）と同じ構成**を
踏襲するよう指定された。単一 `index.html` ＋ GitHub Pages ＋ Apps Script ＋ Googleドライブ。

## 動作確認済みのこと

Playwrightで通しテスト済み。

- サンプルデータでの全画面表示（トップ／大会情報／ランキング／大会結果／お知らせ／制度）
- 大会の絞り込み7種類、月別グルーピング、ページング
- ランキングの区分切り替え（15区分）、内訳の展開、選手の戦績モーダル
- 管理画面：大会追加 → 結果登録 → 承認 → ランキング反映 → 保存 → リロードして復元
- 配点変更の再計算（`topN` を 6→1 にすると 444pt→306pt に変わることを確認）
- XSS：お知らせのタイトルに `<script>` を入れても実行されない。`javascript:` のURLは `href` に出ない
- レスポンシブ：1360 / 820 / 390px で横スクロール発生なし

### 実CDNでの表示確認（2026-08-17 実施・完了）

`cdn.tailwindcss.com` と `unpkg.com/lucide` に実際に取りに行って、1360 / 820 / 390px の
全画面と管理画面の全タブをスクリーンショットで目視確認した。Tailwindのカスタムカラーが
効いていること（`bg-navy` → `rgb(0,31,51)`、`text-brand-red` → `rgb(181,0,0)`）も計算スタイルで確認。
JSエラー・読み込み失敗ともになし。

見つかった崩れは以下4件。すべて修正済み（`index.html`）。

| 症状 | 原因 | 対処 |
|---|---|---|
| 制度ページのグレード表・配点表が390pxで1文字ずつ縦に折り返す | グレードのチップが `nowrap` で幅を占め、本文列が潰れていた | 表を `overflow-x-auto` で包み、`min-w-[560px]` を付けて横スクロールさせる |
| 768〜1023pxでヘッダーのメニュー項目が2行に割れる | 6項目が入りきらないのに `md:`（768px）で横並びに切り替えていた | 切り替えを `lg:`（1024px）に変更。820pxはハンバーガーになる |
| 管理画面の「承認待ち」バッジが2行に割れる（PC幅でも） | 状態列が `w-20` でバッジより狭かった | `w-24` に広げ、バッジを `inline-block` + `whitespace-nowrap` に |
| ランキングの見出し・チップ、選手一覧の所属が狭い幅で1文字ずつ折り返す | 短い語に `whitespace-nowrap` が無かった | 該当箇所に `whitespace-nowrap`。チップの親には `flex-wrap` を足して溢れを防ぐ |

再確認は `node tools/smoke-test.mjs`（実CDN・全項目パス）。

### Apps Script との疎通（2026-08-18 実施・GETのみ完了）

スプレッドシートと Apps Script を作り、ウェブアプリとしてデプロイ済み。
`SHEETS_API_URL` は `index.html` に記入済み。

- 5種類すべての GET が `{"ok":true,"items":[...]}` を返すことを確認
  （`tournaments` / `players` / `results` / `news` / `content`）
- 不正な type には `{"ok":false,"error":"unknown-type"}` を返すことを確認
- ブラウザから実際に読めることを確認（`DATA_SOURCE === 'api'`）。
  CORS は問題なし。ただし `file://` からは弾かれるのでローカル確認はサーバー経由で

> **いまサイトは空です。** スプレッドシートにまだ1件もデータが無いため、
> 大会0件・選手0件で表示されます。3段フォールバックの設計どおり、APIが応答している以上
> `DEFAULT_DATA` のサンプルには戻りません（配点表とサイト文言だけは `DEFAULT_DATA` で補完される）。
> サンプル表示に戻したいときは `SHEETS_API_URL` を一時的に空にする。

`tools/smoke-test.mjs` は画面の回帰テストなので、既定で Apps Script への通信を遮断して
`DEFAULT_DATA` で走るようにした。本番シートの中身に結果が左右されないようにするため。
APIとの疎通込みで見たいときは `USE_API=1 node tools/smoke-test.mjs`。

### サインイン（2026-08-18 時点・生成元の反映待ちで中断）

クライアントID `576378291172-vukiiep7ohj6t7e59be58ioh09pi87gp.apps.googleusercontent.com` を
`index.html` と `Code.gs` の両方に記入済み。

動くようになったところ：

- `CONFIGURED()` が true になり、フッターの「お試しモード」の入口が消えた
- Googleサインインのボタンが描画される

止まっているところ：

- `[GSI_LOGGER]: The given origin is not allowed for the given client ID.` で
  サインインが実行できない（`http://localhost:8000` で確認）

切り分け済み。**クライアントIDの設定ミスではない。**

- Googleの認可エンドポイントに問い合わせると `redirect_uri_mismatch` が返る
  → クライアントは実在し、ウェブアプリケーション型として正しく登録されている
  （`invalid_client` なら存在しない、の意味になる）
- Cloud Console 側では `http://localhost:8000` を JavaScript 生成元に登録済み（本人確認）
- したがって残るは**Google側の反映待ち**。公式に5分〜数時間かかるとされている

localhost の登録は開発時の便宜にすぎないので、**公開先ドメインが決まったらそちらを登録して
本番で検証するほうが早い**。localhost が通るのを待つ必要はない。

確認用スクリプトを `t.mjs`（gitignore済み）に置いてある。`node t.mjs` で再確認できる。
