# 引き継ぎメモ

Claude（Cowork）で作ったものを Claude Code に引き継ぐための記録。
設計の約束事は `CLAUDE.md` に書いてあるので、先にそちらを読むこと。

## この案件の経緯

協会から「全国各地のローカル大会情報のまとめサイトがほしい」「いろんな大会を含めた日本ランキングを作りたい
（硬式テニスのJOPみたいな感じ）」という相談があり、たたき台を作っている段階。

デザインの方向性は何度か往復した結果、**日本バウンドテニス協会サイト（boundtennis.or.jp）の配色・レイアウト準拠**で確定。
実際にブラウザで開いて色を拾った：ネイビー `#001F33`、レッド `#B50000`、背景 `#F1F1F1`、罫線 `#E2E2E2`、本文 `#222`。
書体も協会サイトと同じ `Helvetica Neue → Hiragino Kaku Gothic ProN` の指定にしてある。

アーキテクチャは、依頼者が以前 Claude Code で作った**石川県バウンドテニス協会サイト（ibta.info）と同じ構成**を
踏襲するよう指定された。単一 `index.html` ＋ GitHub Pages ＋ Apps Script ＋ Googleドライブ。

## 動作確認済みのこと

Playwrightで通しテスト済み。

- サンプルデータでの全画面表示（トップ／大会情報／ランキング／大会結果／お知らせ／制度）
- 大会の絞り込み7種類、月別グルーピング、ページング
- ランキングの区分切り替え（15区分）、内訳の展開、選手の戦績モーダル
- 管理画面：大会追加 → 結果登録 → 承認 → ランキング反映 → 保存 → リロードして復元
- 配点変更の再計算（`topN` を 6→1 にすると 444pt→306pt に変わることを確認）
- XSS：お知らせのタイトルに `<script>` を入れても実行されない。`javascript:` のURLは `href` に出ない
- レスポンシブ：1360 / 820 / 390px で横スクロール発生なし

## 未確認のこと

  ローカルでビルドしたTailwind CSSを差し込んで検証した。実CDNでの見た目は要確認

  `Code.gs` はNodeで構文チェックのみ通してある

## 残タスク

### すぐやること

1. **`Code.gs` のプレースホルダを埋める**
   - `GOOGLE_CLIENT_ID` … Google Cloud Console で取得（`apps-script/セットアップ手順.md` の手順5）
   - `ALLOWED_EMAILS` … 管理者のGoogleアカウント
2. **`index.html` の `SHEETS_API_URL` と `GOOGLE_CLIENT_ID` を埋める**
3. **実CDNでレイアウト確認**（ブラウザで開くだけ）
4. **GitHubリポジトリを作って Pages で公開**

### そのあと

5. **ロゴの差し替え。** `index.html` 内のSVGはプレースホルダー
6. **サンプルデータの入れ替え。** 管理画面で本物を入れて「JSON書き出し」→ `DEFAULT_DATA` を差し替え、
   またはスプレッドシートに直接投入
7. **注意バーを消す。** 管理画面「サイト文言」の「上部の注意バー」を空欄にすると帯が消える

### 余裕があれば

8. **結果のCSV一括取込。** いまは1名ずつ選ぶ形。ベスト16以下まで入れるとつらい
9. **`&since=` の活用。** `Code.gs` のGETに期間絞り込みを実装済みだがフロントは未使用。
   結果が数千行になったら使う
10. **BTラリー戦の記録ランキング。** 制度ページに「別立てとする予定」と書いたまま未実装

  どちらを `ALLOWED_EMAILS` に入れるか未回答

  無料で非公開のままにしたいなら Cloudflare Pages に変える

  特に「上位6大会」「G4・G5は最大2大会」「カテゴリ跨ぎの算入」は要議論
- **選手IDの発行と本人紐付け。** 年会費を伴う登録制にするのか、簡易登録にするのか。
  ここで運用負荷が大きく変わる
- **G5（クラブ・サークル主催）の公認基準。** どこまで認めるとランキングの信頼性が保てるか
