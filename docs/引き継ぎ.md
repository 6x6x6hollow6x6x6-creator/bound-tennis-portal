## 制度の方針転換（2026-08-18）

依頼者から実態の説明があり、前提が違っていたことが分かった。

> 交流大会は大会ごとに内容が違い、**クラス分けがない大会が多い**。
> 全国で行われる大会の9割は地方の交流大会で、公式戦と言えるのは
> 全国大会（本戦・県予選）、ブロック選手権（本戦・県予選）、県選手権、
> 国民スポーツ大会（団体戦のみ）くらいしかない。

元の設計は「ローカル大会の成績も同じ物差しで比較できる」前提に立っていたが、
クラス分けが無ければ優勝の意味が大会ごとに違うので、その前提は成り立たない。
配点表もドロー係数も、クラス分けとブラケットがある大会でなければ機能しない。

**決定：ランキングは公式戦だけで組み、交流大会は掲載にとどめる。**

| 項目 | 変更前 | 変更後 |
|---|---|---|
| G4・G5の配点 | 90〜180pt | **すべて0**（掲載のみ） |
| 有効大会数 | 上位6大会 | **4大会**（公式戦は年に数回しかない） |
| 掲載条件 | 2大会以上の出場 | **1大会以上** |
| 対象種目 | 全種目 | **シングルス・ダブルス・ミックスダブルス**（`settings.rankEvents`） |

団体戦は掲載できるようにしたが、ランキングには算入しない。
出場していない控えの選手にも順位が付いてしまい、貢献度を測れないため。
チーム単位の団体戦ランキングを別立てにするかは未決（下の未決事項）。

実装上の要点：

- 配点0のグレードは `computeRankings` が結果ごとスキップするので、集計から完全に外れる
  （出場回数にも数えられない）。設定を戻せば元の挙動に戻る
- 制度ページの「掲載のみ」バッジと文言は、**配点から自動判定**している。
  固定テキストに書くと設定を変えたときに食い違うので、書かないこと
- 種目は2本立て。`EVENTS_ALL`（掲載できる種目・団体戦とBTラリー戦を含む）と
  `settings.rankEvents`（ランキング対象）
- 管理画面の結果登録で、対象外の種目を選ぶとポイント欄が「—」になり
  「ランキングには算入されません」と出る。数字を見せると誤解を生むため

ついでに直した既存の不具合：種目がBTラリー戦だけの大会を選ぶと、種目の選択肢が空のまま
登録でき、`ev` が空文字の結果ができてしまっていた。保存を止めるようにした。

## 地域差・ドロー数の是正（2026-08-18）

依頼者からさらに指摘があった。

> ブロックや都道府県でレベルや参加人数に偏りがある。北海道はブロック大会も北海道だけで
> くくられているので有利になる。地域によっては参加した瞬間に入賞が決まることもある。

調べたところ、係数表に穴があって実際に順位が逆転していた。

```
修正前
  G2 2名ドローで優勝（1試合勝つ）      = 300 pt
  G3 32名ドローで優勝（5試合勝つ）      = 360 pt   ← ほぼ同じ
  G2 4名ドローで初戦負け（ベスト4確定） = 135 pt
  G3 32名ドローでベスト8（3試合勝つ）   = 101 pt   ← 負けた人のほうが高い
```

原因は2つ。**係数表の最小バケットが「4名以上」しかなく、それ未満は全部0.50に落ちていた**こと
（`drawCoef` は最小バケット未満のとき最後の行の係数を返す。1名でも0.50）。
もう1つは、**成績ラベルが「何人抜いたか」の代理指標として機能していない**こと。

対処（すべて実施済み）：

1. **勝ち数0の成績は「出場」に読み替える**（`winsNeeded()` / `awardedPoint()`）。
   ドロー数と成績から必要勝ち数を計算できる（32名ドローの優勝＝5勝、4名ドローのベスト4＝0勝）。
   設定 `winBasedPlaces` を false にすると元の挙動に戻る
2. **係数表に `2名以上＝0.30` を追加**して下限を作った
3. **グレードは競う範囲で決めるルールを制度ページに明記**（`about.gradeRule`）。
   実質1県のブロック大会はG3として扱う。コード変更ではなく運用ルール

```
修正後
  G2 2名ドローで優勝                    = 180 pt
  G2 4名ドローで初戦負け                =   9 pt   ← 出場扱いになった
  G3 32名ドローでベスト8（3試合勝つ）   = 101 pt   ← 逆転が解消
```

あわせて、**ドロー数未入力（0）だと係数0.50が黙って適用されていた**問題も直した。
事務局が入力を忘れると半分のポイントが付いてしまう状態だったので、登録時に弾くようにし、
入力欄にも警告を出すようにした。

スモークテストに「勝ち数0の入賞は出場扱い」「勝った選手のほうが点が高い」を追加してある。

## レーティング化に向けた準備（2026-08-18）

依頼者との議論で出た論点。

> 北海道だけブロック大会のグレードが違う時点で公平感はない。対戦相手のレーティングでの
> 重みづけができるのが一番いいが、データ集計に数年かかる（過去の履歴を集めてもいい）。
> 東北ブロックで勝ち上がるのと関東ブロックで勝ち上がるのではかなりレベルに開きがある。

**決定：記録の粒度を上げる（全参加者を記録できるようにする）＋ ブロック較正は全国大会の実績で行う。**

### なぜ記録の粒度を先に上げるのか

**データは遡って作れない。** レーティングの実装自体は100行程度で、ボトルネックは常にデータ。
いま上位8人だけで運用すると、数年後に「レーティングをやろう」となったとき、
その数年分は使えない。逆に全参加者を記録しておけば、あとから方式を選べる。

粒度の段階：

| 段階 | 記録する内容 | 後でできること |
|---|---|---|
| 以前 | 上位8人 | 配点表による集計のみ |
| **いまここ** | **全参加者** | フィールドの強さ補正、参加実態の把握 |
| 次 | 対戦結果（誰が誰に勝ったか） | Elo / Glicko によるレーティング |

Eloは順位では計算できず、対戦単位の記録が要る。目安は1人あたり15〜25試合で安定しはじめる。
公式戦が年4〜5大会・1大会3〜5試合なら2〜3年分。過去のドロー表が残っていれば、
1大会のPDFから数十試合ぶん復元できるので、履歴収集で短縮はできる。
ただし全国・ブロック・各県に散らばっており、県協会への依頼が要る。技術ではなく調整の仕事。

**見落としやすいコスト**：レーティングは説明しにくい。「なぜ優勝したのに点が下がったのか」に
事務局が答えられる必要がある。配点表なら表を見せれば済むが、レーティングはそうはいかない。
設計方針③（事務局が手作業で回せる程度に単純）と正面から衝突する。

### 実装したもの：まとめて貼り付け

管理画面の「結果」タブ下部。1行に1名、`成績,選手IDまたは氏名`。タブ区切りも可。
列の順番が逆でも読む。氏名は空白を無視して照合する。

安全側に倒してある点：

- 名簿にない選手、不明な成績はエラーとして列挙し、**候補から外す**
- **同じ選手が複数行にいたら、その選手を丸ごと候補から外す。**
  どちらの成績が正しいか決められないため。片方を勝手に採ると誤ったポイントが入る
- 同姓同名が複数いる場合は選手IDを要求する
- 登録前に必ずプレビュー（成績・選手・所属・ポイント）を出す

### まだ実装していないもの：ブロック較正

**データが1件も無い状態で自動較正を実装しても、正しく動いているか検証できない。**
全国大会の結果が数回分たまってから作る。仕様は下記。

- 各ブロック代表が**全国大会**でどこまで勝ち上がったかを集計し、ブロック係数を出す
- 必要なデータは全国大会の結果だけ。どのみち必ず集めるもの
- 「協会がブロックの格を決めた」ではなく「全国大会の実績がこう出ている」と言えるので説明しやすい
- 精度はEloに劣るが、全ブロック一律G2よりは確実にまし
- 設定に `regionCoef`（地域ごとの係数）を足し、G2の大会に掛ける形を想定

## シード制度への対応（2026-08-18）

依頼者から競技構造の説明があった。**これが制度上いちばん効いた指摘。**

> 前年の全国大会で3位までに入ると翌年の全国大会のシード枠が与えられるため、
> 翌年の全国大会予選やブロック大会（予選・本戦とも）には参加しなくなる。
> ブロック大会本戦の優勝者には全国大会のブロックシード枠が与えられる。
> 基本的にどの県も全国大会に一人でも多く出そうとする。

つまり**強い選手ほど出場する大会が少ない**。合計方式はこれと構造的に相性が悪い。試算した結果：

```
全国大会で優勝したシード選手      1000 pt
予選から積み上げた非シード選手    1572 pt   ← 572pt 上
全国大会ベスト4のシード選手        450 pt   ← 非シードの29%
```

**日本一がランキング1位になれない状態だった。**

### 検討した案

| | 1位 | 2位 | 3位 | 4位 | 5位 |
|---|---|---|---|---|---|
| 現状（合計） | 非シード 1572 | 全国優勝 1000 | 県のみ 712 | 全国ベスト4 450 | 全国ベスト8 280 |
| 案A：平均のみ | 全国優勝 500 | 非シード 393 | 県のみ 237 | 全国ベスト4 225 | 全国ベスト8 140 |
| **案B：平均＋G1×2** | **全国優勝 1000** | **全国ベスト4 450** | **非シード 393** | **全国ベスト8 280** | **県のみ 237** |

案Aは平均にするだけでは足りず、全国ベスト4が県だけ回る選手より下に残る。
**案Bを採用。**

### 実装

1. **平均方式**（`settings.averaged` / `minDivisor`）
   BTP＝上位N大会の合計 ÷ `max(採用大会数, 2)`。
   除数を「採用大会数」にしてあるので上位4で頭打ちになり、**多く出場して損をすることはない**。
   交流大会は0点なので `computeRankings` に入らず、分母にも影響しない。
   `averaged: false` にすると合計方式に戻る
2. **G1の配点を2倍**（優勝2000／ベスト4 900）。G2との比が1.67倍→3.3倍
3. ランキングの内訳は「合計 ÷ 除数 ＝ BTP」と分解して表示。
   構成比の棒グラフは合計を基準にしている（`row.sum`）

### 依頼者が提案した別案（不採用）

「シード枠に相当ポイントを与える」案もあった。合計方式のまま説明が簡単という利点はあるが、
**架空の成績を作る**ことと、**シードで出て初戦負けした選手にもブロック優勝相当が入ってしまう**
のが難点。案Bは架空の記録なしに同じ公平性を得られるので採用しなかった。

### 全国大会のドロー表

依頼者いわく、**日本バウンドテニス協会の公式サイトから結果付きで取得できる**。
これでブロック較正の材料はすぐ揃う（各ブロック代表が全国でどこまで勝ったか）。
ドロー表があれば対戦結果も復元できるので、レーティングの素地にもなる。

## 集計期間の延長と、制度の限界の明記（2026-08-18）

依頼者から、県ごとの選手層の厚さの違いについて指摘があった。

> 神奈川など一部の県は選手層が厚いので、他県でなら優勝できるレベルでも入賞できず、
> なかなか全国大会に出られない。実力が拮抗しているので毎年全国に出る人間が変わる。
> 一方、地方では予選に参加すれば全国大会出場の切符がもらえて毎年同じ人が出る。

### これはポイント制では解けない

ポイントは「その大会で何位だったか」に与えられるので、**どの大会に出られたかで決まる**。
神奈川の3番手が県予選で消えれば点が入らない。実力があってもランキングに現れない。

配点表をどういじっても直らない。県予選のグレードを上げれば、今度は
「県予選で勝つほうが全国に出るより得」という別の歪みが出る。
**測っている対象が「実力」ではなく「所属県での相対順位」だから。**

これを解けるのはレーティングだけ。Eloは「誰に勝ったか」で動くので、
全国大会に出られなくても強い相手に勝てば上がる。
依頼者が当初から「対戦相手のレーティングでの重みづけが一番いい」と言っていたのは構造的に正しい。
いま見つかっている問題（ブロック間格差、県ごとの層の厚さ、シード制度）は
すべて同じ根から出ていて、すべてレーティングなら解ける。

**なお、全国大会の結果だけではブロック較正の材料として不十分**という点も判明した。
あれで測れるのは「各ブロックの代表がどれくらい強いか」であって「層が厚いか」ではない。
ブロック係数を出す目的には足りるが、層の厚さまで測るには県予選のドロー表が要る。

### いま入れた対処

1. **集計期間を52週→104週**、52週より古い成績は**0.5倍に減衰**（`settings.decay`）。
   全国大会が2回分入るのでブレが減る。シード選手は年1大会なので特に効く。
   `decay` は `[{weeks, coef}]` の配列で、空にすれば減衰なしに戻る
2. **制度の限界を制度ページに明記**（`about.limits`）。
   出場機会の差を補正できないこと、将来的にレーティングへの移行を検討していることを書いた。
   あとから「あの人のほうが強いのにランキングが低い」と言われたとき、
   隠していなかったことが効く

ランキングの内訳では、減衰した成績を `255（510×0.5）` のように分解して表示する。

## カテゴリ移動への対応（2026-08-18）

依頼者からの指摘。

> 年齢が上がってフリーからミドルへ、ミドルからシニアへというクラスの移動もあるし、
> 前年はシニアで出たけど次の年は人がいなかったからミドルで出るとかもある。

**実装に2つ穴があった。どちらも修正済み。**

### 穴1：フリーだけが特別扱いされていた

旧実装は `if (r.cat === 'フリー')` のときだけ上位カテゴリに算入していた。
つまり**シニアの選手がミドルに出ると、その成績はシニアのランキングに入らなかった**。
人数の都合でミドルに回ることがあるという実態と合っていない。

出場したカテゴリより対象年齢が上のカテゴリすべてに算入するよう一般化した。
フリー→ミドル・シニア、ミドル→シニア。逆は不可。

### 穴2：大会当日の年齢で判定していた

旧実装は `ageAt(p, t.date)`（大会当日の年齢）で判定していた。これだと
**誕生日でカテゴリが上がった選手が、直前までの成績を全部失う**。
60歳になった瞬間、シニアのランキングに実績ゼロで現れて最下位から始まることになる。

集計基準日の年齢（`ageAt(p, as)`）で判定するよう変更した。
集計期間は2年なので、この違いが影響するのは直近2年で境界を跨いだ選手だけ。
まさにその移行期の選手を救うための変更。

確認した挙動：

```
62歳の選手がミドルの部で優勝
  フリー → 掲載なし（逆方向には入らない）
  ミドル → 入る
  シニア → 入る          ← 旧実装では入らなかった

1年半前にフリーで優勝、いま61歳（当時59歳）
  フリー・ミドル・シニア すべてに入る   ← 旧実装ではシニアに入らなかった
```

### レーティングに移る場合

レーティングは「誰に勝ったか」で計算するので、**カテゴリの区別自体が不要になる**。
選手単位で1つのレーティングを持てばよく、この問題は消える。
表示のためにカテゴリ別の一覧を出すことはできる。
